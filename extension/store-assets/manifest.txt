Ashley Bridge 4.0.0: store assets

Made 2026-09-29 (the screenshots between 19:03 and 19:08 UTC). The screenshots are the real release build
(extension/.output/chrome-mv3, the 4.0.0 build in the store zips; the zips were made again afterwards for a
README change in the sources zip, and the built files are the same except the "generated" time stamp in
framework/manifest.json) loaded into Playwright's Chromium (Chrome for Testing 153) with a fresh profile, a 1280x800
viewport and the light colour scheme, driven against the mock Open OnDemand portal
(extension/mock-ood/server.mjs) served over https at localhost:8443 with a self-signed certificate, the mock
user st1234 (--user st1234), and MOCK_LOGGED_IN=false so the Claude sign-in step is reached. There is no key:
the extension read the account name the mock's dashboard shows ("Logged in as st1234") and asked the real
access service (the access_check address in https://openspineconsortium.com/ashley/services.json), which
answered approved:true for st1234. The withdrawn-versions list was fetched by the extension itself once the
agreement was accepted (the list issued 2026-09-29 15:32 UTC, nothing withdrawn). The mock home was seeded
with .hpcworker/profile.json and .hpcworker/VERSION = 3 (the bundled framework version) so the strip found the
tool installed; the mock's tool prints and records the portal's own home, /home/st1234, in place of the mock
home's real path.

How the run was driven: the agreement was accepted on the setup page as a person does (scrolled to the end,
four boxes ticked, a typed name, "Accept and Continue"). The toolbar button was pressed on the portal tab with
the DevTools protocol's Extensions.triggerAction (the action a click runs), and the browser's own permission
prompt was answered with Windows UI Automation (its Allow button); no extension state was edited. Before that
click the side panel was switched off with chrome.sidePanel.setOptions, so the background's own fallback
opened the strip as a tab, which is what is captured at 1280x800; in Chrome and Edge a person sees the same
strip in the side panel beside the portal. The full request log of this run (and of the not-approved run with
zz9999) is in e2e/. Nothing in the images was drawn by hand or composited. Each image was looked at: no machine
path and no personal name appears in any of them.

Caveats
- The strip is captured as a tab, not in the side panel (see above); the content is the same page.
- 03b and 04 were captured again from the 4.0.0 build and came out byte-identical to the 3.0.0 images: those two
  steps did not change.
- The agreement text inside the dialog names the licensor (the copyright line and the parties clause of
  LICENSE.txt, the first lines of PRIVACY.md); neither is inside the visible part of 01 or 01b.
- 02, 04b: "Connected - phone - HEAD" and "student@example.edu" are the mock's stand-in Remote Control and
  Claude sign-in values, not the reviewer's or anyone's account.
- 04, 03: the claude.ai tabs the extension opened during the run (the mock's sign-in URL with a mock client id,
  and the mock's environment link) loaded claude.ai itself; the harness stubbed their assets only (e2e/run-A-*.txt
  says which requests). They are not in any image.
- The time stamps in 02, 04b and 05 are this machine's local time (US Eastern) as the extension shows them; the
  "checked ... UTC" in check 1 and the access card is UTC.

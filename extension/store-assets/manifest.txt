Beethoven 7.0.0: store assets

Made 2026-09-30 between 01:52 and 01:56 UTC (2026-09-29 evening, US Eastern) for 7.0.0, the release in which the
public name became Beethoven. Every image carried the old name before, so all twelve were made again: the nine
screenshots in run H, the three rendered images from src/. The agreement in them is LICENSE.txt version 6 and
PRIVACY.md version 7 (TERMS_VERSION 6), the texts 7.0.0 ships.

How the screenshots were made (run H, e2e/run-H-store-screenshots-reviewer-recipe-st1234.txt): the release build
(extension/.output/chrome-mv3, 7.0.0, framework 6 bundled) loaded into Playwright's Chromium (Chrome for Testing 153)
with a fresh profile, a 1280x800 viewport and the light colour scheme, driven against the mock Open OnDemand portal
(extension/mock-ood/server.mjs) over https at localhost:8443 with a self-signed certificate, exactly as the store
reviewer's recipe runs it: --user st1234, MOCK_LOGGED_IN=false and the mock's own home seeding (the stand-in set up as
the account's own copy at the version the build carries, so the strip finds the tool installed and uploads nothing;
Details reads "tool: your own copy, version 6"). There is no key: the extension read the account name the mock's
dashboard shows and asked the real access service at beethoven-access.openspineconsortium.workers.dev, which answered
approved:true for st1234. The site pages under https://openspineconsortium.com/beethoven/ were not published yet, so
the harness answered the two site requests the extension makes (services.json and killlist.json) with the files the
site build and the kill-list signer had just written into the site repository; nothing else was routed. The
agreement was accepted on the setup page as a person does (scrolled to the end, four boxes ticked, a typed name,
"Accept and Continue"); 01 was taken before anything was touched and 01b once the four boxes were ticked and the name
typed, before the button was pressed (no request had gone to the vendor by then). The toolbar button was pressed on
the portal tab with the DevTools protocol's Extensions.triggerAction (the action a click runs), and the browser's own
permission prompt was answered with Windows UI Automation (its Allow button); no extension state was edited. Before
that click the side panel was switched off with chrome.sidePanel.setOptions, so the background's own fallback opened
the strip as a tab, which is what is captured at 1280x800; in Chrome and Edge a person sees the same strip in the side
panel beside the portal. Nothing in the images was drawn by hand or composited. Each image was looked at, and the
harness checked the text on screen in each one for a machine path, the Windows user name and the old product name:
none appears in any of them.

Caveats
- The strip is captured as a tab, not in the side panel (see above); the content is the same page.
- The agreement text inside the dialog names the licensor (the copyright line and the parties clause of LICENSE.txt,
  the first lines of PRIVACY.md); none of it is inside the visible part of 01 or 01b (01 shows only the top edge of
  the full-text box, 01b none of it). The harness's text record for 01 lists that text because the box's top edge is
  in view; the image shows none of it.
- 02, 04b: "Connected - phone - HEAD" and "student@example.edu" are the mock's stand-in Remote Control and Claude
  sign-in values, not the reviewer's or anyone's account.
- 03, 04: the claude.ai tabs the extension opened during the run (the mock's sign-in URL with a mock client id, and
  the mock's environment link) are not in any image; the e2e log says which of their requests were stubbed.
- 03, 03b, 04: the output box and the terminal show the tool's command name and paths in the mock's home
  (/home/st1234/.hpcworker/...), as the tool prints them; the extension shows raw command output as it is.
- The time stamps in 02, 04b, 05 and 05b are this machine's local time (US Eastern) as the extension shows them; the
  "checked ... UTC" in check 1 and the access card, and the audit log's times, are UTC.

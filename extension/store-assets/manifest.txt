Beethoven 8.0.0: store assets

Made 2026-09-30 between 14:49 and 14:53 UTC for 8.0.0, the release that is distributed only through the
private Chrome Web Store listing, binds each approved account to one installation, and carries no copy of
the cluster tool. All nine screenshots were made again: the setup page now says what the approval check
sends (the installation identifier) and that an approval covers one installation, and the agreement in
them is LICENSE.txt version 7 and PRIVACY.md version 8 (TERMS_VERSION 7), the texts 8.0.0 ships. The
two rendered images from src/ (the tile and the marquee) name no version and no browser and are unchanged
since 7.0.0. The Edge Add-ons logo (edge-store-logo-300x300.png and its src/ page) was removed: there is
one store and one private listing.

How the screenshots were made (run L, e2e/run-L-store-screenshots-reviewer-recipe-st1234.txt): the release
build (extension/.output/chrome-mv3, 8.0.0, no framework bundled) loaded into Playwright's Chromium
(Chrome for Testing 153) with a fresh profile, a 1280x800 viewport and the light colour scheme, driven
against the mock Open OnDemand portal (extension/mock-ood/server.mjs) over https at localhost:8443 with a
self-signed certificate, exactly as the store reviewer's recipe runs it (docs/store/LISTING.md): --user
st1234, MOCK_LOGGED_IN=false and the mock's own home seeding (the account already set up on the mock's
stand-in for the lab's shared copy, at the mock's default path /lab/shared/hpcworker/current and its
default version 5, so the strip finds the tool and runs no install; Details reads "tool: the lab's shared
copy, version 5"). There is no key: the extension read the account name the mock's dashboard shows and
asked the real access service at beethoven-access.openspineconsortium.workers.dev, sending install_id with
the check, and the service answered approved:true for st1234 (the reviewers' account is accepted from any
installation there, so each reviewer's own installation works). services.json and killlist.json were
answered by the harness from the files in the site repository; nothing else was routed. The agreement was
accepted on the setup page as a person does (scrolled to the end, four boxes ticked, a typed name, "Accept
and Continue"); 01 was taken before anything was touched and 01b once the four boxes were ticked and the
name typed, before the button was pressed (no request had gone to the vendor by then). The toolbar button
was pressed on the portal tab with the DevTools protocol's Extensions.triggerAction (the action a click
runs), and the browser's own permission prompt was answered with Windows UI Automation (its Allow button);
no extension state was edited. Before that click the side panel was switched off with
chrome.sidePanel.setOptions, so the background's own fallback opened the strip as a tab, which is what is
captured at 1280x800; in Chrome a person sees the same strip in the side panel beside the portal. Nothing
in the images was drawn by hand or composited. Each image was looked at, and the harness checked the text on
screen in each one for a machine path, the Windows user name and the old product name: none appears in any
of them.

Caveats
- The strip is captured as a tab, not in the side panel (see above); the content is the same page.
- The mock's stand-in for the lab's shared copy reports version 5 (the mock's default, which the reviewer's
  recipe uses); the real shared copy at Wayne State is framework 8. Run I used --shared-version 8.
- The agreement text inside the dialog names the licensor (the copyright line and the parties clause of
  LICENSE.txt, the first lines of PRIVACY.md); none of it is inside the visible part of 01 or 01b.
- 02, 04b: "Connected - phone - HEAD" and "student@example.edu" are the mock's stand-in Remote Control and
  Claude sign-in values, not the reviewer's or anyone's account.
- 03, 04: the claude.ai tabs the extension opened during the run are not in any image; the e2e log says which
  of their requests were stubbed.
- 03, 03b, 04: the output box and the terminal show the tool's command name and paths in the mock's home
  (/home/st1234/.hpcworker/...), as the tool prints them; the extension shows raw command output as it is.
- The time stamps in 02, 04b, 05 and 05b are this machine's local time (US Eastern) as the extension shows
  them; the "checked ... UTC" in check 1 and the access card, and the audit log's times, are UTC.
